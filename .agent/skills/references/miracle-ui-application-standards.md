# Miracle UI application standards

Apply these rules to every handwritten Angular application file. Preserve stricter compatible repository rules and exclude generated transport code from style automation.

- Put each Angular component in its own named folder. Use sibling `.component.ts`, `.component.html`, and `.component.scss` files whose `templateUrl` and `styleUrl` metadata resolve exactly to those companions. Colocate a `.component.spec.ts` when the component has focused behavior. Prefer `app/components/pages`, `app/components/modals`, and `app/components/shared` unless the repository has a more specific sound convention.
- Use this application-level folder structure by default: `app/components/{pages,modals,shared}`, `app/constants`, `app/guards`, `app/interceptors`, `app/messages`, `app/models`, `app/pipes`, `app/providers`, `app/routes`, and `app/services`. Put generated and mock clients in `app/services/http/client/{generated,mock}`, handwritten HTTP adapters in `app/services/http`, and application services directly in `app/services`. Reserve `app/messages` for `MessageBusService` contracts. Do not mix these concerns into feature folders or a catch-all `core` folder.
- Name handwritten generated-client adapters `*Service` and place them under `app/services/http`; place application use-case collaborators under `app/services`. Reserve `components` for Angular components; colocate only component templates, styles, and focused component specs there.
- Separate every class member with exactly one empty line; comments do not replace that empty line.
- Separate the final import from the first top-level declaration with exactly one empty line. Also use exactly one empty line between sibling top-level type, interface, enum, class, function, and variable declarations.
- In spec files, separate sibling `describe`, `it`, `test`, `beforeEach`, `afterEach`, `beforeAll`, and `afterAll` calls with exactly one empty line, including focused or skipped variants. Do not apply this rule inside chained expressions or nested callback statements that are not sibling test blocks.
- Order class members as fields, properties/accessors, constructor, recognized public static constructors/factories, public methods, protected methods, then private methods. Classify private and protected static helpers by access, not as factories. Treat only clearly named public factories such as `create*`, `from*`, `of`, `parse*`, `hydrate*`, `empty*`, `default*`, or `initial*` as static constructors.
- Use multiline constructor, method, and accessor bodies, including empty bodies. Put each statement on its own line, including statements in nested blocks.
- Configure a check-only repository style gate when the formatter or linter does not enforce these rules. Do not auto-reorder class members or apply an unsafe structural `--fix`.
